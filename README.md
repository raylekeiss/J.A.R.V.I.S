# ちいさな世界史AI

## Qwenブラウザ試作版

`/qwen/` でQwen3-0.6Bを端末内実行します。従来の自作モデルはトップページにあります。

- 外部の生成APIやAPIキーは使用しません。質問は送信せず、Web Worker内のONNX Runtime / WebAssemblyでCPU推論します。
- 初回だけ明示操作で約534MBの固定版モデルとトークナイザーをHugging Faceから取得します。実行ファイルと合わせても1GB未満です。モデル重みはGitには保存していません。
- 既存の `transformers-cache` と固定版URLを引き継ぎます。ページを開くと実際の保存済みファイルを確認し、揃っていれば再取得せず自動起動します。保存が消えていた場合は勝手にモデルをダウンロードしません。取得したファイルの保存失敗は短い状態表示で知らせます。保存の永続化も要求しますが、ブラウザの許可や空き容量によっては削除されるため、永久保存は保証できません。
- 対応ブラウザでは重みをストリーム圧縮して保存し、読み出し時に展開します。実モデルのgzip計測では524,589,133バイトが485,566,555バイトになりました。これは保存容量の削減であり、実行時メモリの削減ではありません。圧縮後も保存容量が足りない場合は保存できない旨を表示します。
- キャッシュからの読み出しは「保存済みモデルを読み込み中」と表示します。ページを開き直す際のメモリへの読み込み・初期化は必要です。保存場所をGitHubへ変えても端末の計算やメモリ使用は減りません。GitHub Pages自体ではQwenのサーバー推論を実行できません。
- トークン処理の間にWorkerのメッセージ処理を挟み、通常の生成停止では読み込み済みモデルを保持します。停止が10秒間確認できない異常時はWorkerを終了し、その場合だけ再起動が必要です。
- 取得の進行が2分間確認できない場合、または起動が90秒間確認できない場合もWorkerを終了します。タイムアウトは端末が非対応である証明ではありません。
- 画面上部の説明パネルは設けず、操作と短い状態表示だけにしています。初回の取得容量は開始ボタンに表示します。
- 会話履歴は直近3往復・入力640トークン・出力160トークンまでです。世界史の追加学習、既存NumPy重みや教材の移植は未実施です。歴史の誤答や中国語での返答が確認されており、正確な教材としては未完成です。
- iPhone SE（第2世代）では取得100%から起動が進まない報告があり、SE2対応は確認できていません。PCのNode.js/WASMでグラフの再最適化を無効にして初期化ピークメモリが約2101MiBから1785MiBに減りましたが、SE2での必要メモリを測った値ではありません。
- 従来の定期学習はNumPy版だけを更新します。Qwen版が自動で追加学習される構成ではありません。

開発: `npm ci --ignore-scripts`、`npm run test:qwen`、`npm run build:qwen`。画面コードはdocs/qwenに保存し、実行ライブラリとWASMはバージョン指定のjsDelivrから取得します。

NumPyだけで実装した文字単位のTransformerと、世界史・日常会話のチャット画面です。OpenAI APIキーは使用しません。

## ローカルで使う

`pip install -r requirements.txt` の後、`start_chat.py` を起動します。

1. 保存済みモデルで会話する。
2. inboxまたはadd.jsonlを使って候補を追加学習し、評価に合格した場合だけ更新する。
3. 全データで候補を作り直し、評価に合格した場合だけ更新する。

初回モデルがない場合だけ通常の初期学習を行います。黒いサーバー画面を閉じるとローカルの会話も止まります。ブラウザ版はdocs/index.htmlとモデルをGitHub Pagesで配信すると、ブラウザ内で推論できます。

## 自動学習

inboxへ290行単位のJSONLを追加するとGitHub Actionsが候補を学習・評価します。件数が300組を超えただけで初期化することはありません。合格時だけ学習済みデータとモデルを保存し、Pagesへ公開します。不合格時のモデル・データは変更せず、結果をActionsの成果物に保存します。

```json
{"user":"科挙とは","assistant":"隋の文帝が始めた筆記試験による役人の選抜制度です。"}
```

新規ファイルはUTF-8、各290行、userとassistantの2項目を使います。質問25字以内、回答1文40字以内、です終止で、問い返しは入れません。訂正はdata/correctionsへ置き、同じ質問の回答を置き換えます。

使い方・評価基準・教材作成と定期タスクの指示は [AUTOMATION.md](AUTOMATION.md) を参照してください。GitHub Actionsの週次実行は待機データの処理であり、教材生成にはChatGPT側の定期タスクが別途必要です。

## 検証

```
python -m unittest discover -s tests -v
python -m scripts.evaluate
```

evaluation/cases.jsonlの固定評価と新規例の確認問題で比較します。未知の知識への一般化や、歴史的正確性を全面的に保証するテストではありません。
